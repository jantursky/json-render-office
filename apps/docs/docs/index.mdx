[json-render](https://github.com/vercel-labs/json-render) lets a model write a JSON spec that is constrained to a Zod catalog of components. The packages here are renderers for that spec. Instead of a web page or a PDF, they write real Office files: slides with text boxes, tables and native charts, and Word documents with headings, lists and tables that you can edit afterwards.

The current version is {{version}}. See the [changelog](/changelog) for what each release changed.

| Package              | Output                                                           | Built on                             |
| -------------------- | ---------------------------------------------------------------- | ------------------------------------ |
| `json-render-pptx`   | `.pptx` slides                                                   | `vue-pptx-document`                  |
| `json-render-docx`   | `.docx` documents                                                | `vue-docx-document`                  |
| `json-render-report` | One report catalog: a web page, a `.pptx` deck and a `.docx`     | The two above and `@json-render/vue` |
| `json-render-office` | Shared spec walker, safe image loading, theme and schema helpers | Used by the others                   |

## How it works

A spec is a flat object: a `root` key and an `elements` map. Each element has a `type`, `props` and `children` (a list of keys). A renderer walks the tree from the root, looks each type up in a registry of components and mounts the result with the Office writer. Text, tables and charts come out as real Office objects, so the files stay editable.

The standard components never take coordinates. A slide picks a layout and its children are placed in reading order, so the model describes content and the renderer decides where it goes.

Bad content is not an error. A missing child, an unknown type or a bad prop is skipped and reported as a warning, which is what lets a spec that is still streaming render at every step. Render functions reject only when the writer itself fails.

## Status

Features are checked only by opening the files in LibreOffice {{libreoffice}}. Everything else is unverified, and [Limitations](/limitations) lists what is missing. PDF output is not part of these packages.
